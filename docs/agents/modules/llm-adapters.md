# LLM Adapters

The root generated `AGENTS.md` is the intended cross-LLM entrypoint.

## Policy

- **A root `CLAUDE.md` adapter IS required** and is generated alongside
  `AGENTS.md` by `bin/agent-runtime install` (via the lower-level
  `bin/install-agent-docs` implementation). Claude Code auto-loads `CLAUDE.md`
  (and its `@imports`) but does **not** auto-load `AGENTS.md` — proven
  2026-06-20 when multiple Claude sessions skipped the DevOps cycle entirely
  because `AGENTS.md` was never in their context. Source:
  `docs/agents/claude.md`.
- The adapter stays **thin**: a short inline DevOps-Routing gate plus `@AGENTS.md`
  (which Claude Code expands), with no duplicated project facts.
- Do **not** create a root `CODEX.md` — Codex reads `AGENTS.md` natively.
- App-level `CLAUDE.md` files were deleted on 2026-06-14 after final review.
  Current app context lives in README/RUNBOOK/topic docs.

## Claude Compatibility Smoke Test

Status, 2026-06-20: the 2026-06-14 read-only smoke test was a **false pass** — it
told Claude to read the docs and answer, which tests reading, not auto-loading.
In real sessions Claude Code never auto-loaded `AGENTS.md`, so the DevOps cycle
was invisible and got skipped on bare prompts. Fix shipped: a root `CLAUDE.md`
adapter (inline routing gate + `@AGENTS.md`), generated by
`bin/agent-runtime install`.

Compatibility verdict: a root `CLAUDE.md` adapter **is required** for Claude Code.
Prefer a **behavioral** test over the read-only one below: give a fresh Claude
session a bare feature prompt and confirm it creates a task + worktree and runs
`bin/dor-check` before editing.

Re-run this from `/Users/alex/projects` after major agent-doc changes or Claude
CLI upgrades:

```bash
claude -p \
  --permission-mode dontAsk \
  --allowedTools "Read,Glob,Grep,LS" \
  --no-session-persistence \
  --max-budget-usd 0.50 \
  "Read-only compatibility smoke test. You are starting a fresh coding-agent session in the current directory. Do not edit files. Use local repository files to answer: 1. What is the canonical agent entrypoint? 2. Which repo is the documentation source of truth? 3. What is the LLM adapter policy for CLAUDE.md/CODEX.md? 4. What are the first three docs you would read next for a normal task? Keep the answer concise and mention the files you relied on."
```

Success criteria:

1. Names `/Users/alex/projects/AGENTS.md` as the canonical agent entrypoint.
2. Names `mcritchie-studio` as the documentation and bootstrap anchor.
3. Says root `CLAUDE.md` is a thin required adapter, while root `CODEX.md`
   should not be created.
4. Chooses current neutral docs such as `docs/ECOSYSTEM.md`,
   `docs/agents/modules/culture.md`, or task-relevant modules as next reads.
5. Does not treat app `CLAUDE.md` files as active truth.

If the smoke test fails because Claude ignores the root adapter or does not
expand `@AGENTS.md`, fix `docs/agents/claude.md`, run `bin/agent-runtime install`,
and re-run the smoke test.
