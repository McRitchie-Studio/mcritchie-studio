# Testing

> **When to read this:** Writing new tests, debugging failures, or setting up Playwright/CI.

## The pre-flight (before `submitted`)

- `bin/fast-check <task>` — the builder's **optional local pre-flight** (~1 min): runs the tests the branch diff maps to (path convention, a tool's test family, a subject-identity grep fallback) + the curated core spine (`config/fast_cert_spine.yml`) + `rubocop` on the **changed files only**, prints its result, and **records nothing on the task**. The PR's settled green GitHub CI is the one verdict per tree — CI runs the full suite + `test:system` per push — and `bin/dor-check` reads that alone. `--list` prints the selection without running. When the diff is wide enough that the mapped lane is **CAPPED**, the lane falls back to the convention twins, or to the spine alone, and says so; when no test lane can run at all (a diff that maps to nothing on a checkout with no spine) it says that too and exits 0. `bin/ship` runs it at step 2/8 and carries on whatever it says; a red lane there almost always means a red CI ten minutes later.
- **The local full-suite cert retired on 2026-09-24** (`retire-local-cert-evidence`, DevOps v3 phase 2b): `bin/full-suite-check`, its fingerprint-bound receipts, the bypass and deferral hatches and the cert root/tree/orphan guards are gone. Nothing local stands in for CI's verdict; nothing local needs to. `bin/lib/ci_test_command.rb` still resolves "what CI's Ruby suite amounts to, as one command" for the release gate (`bin/release.rb`), which runs it in an isolated gate workspace.
- Never run two local suites concurrently on this machine (parallel suites SIGSEGV Ruby) — serialize when sessions overlap.

## Playwright E2E Tests

- `npm test` — runs all Playwright tests. **The spec counts live in `config/e2e_lane.yml` (`total_specs` / `quarantined` / `executed`) and are deliberately not repeated here** — that file is the contract both guards read, and every copy of the numbers in prose has rotted within days of being written.
- `npm run test:headed` — runs with visible browser
- `npm run test:ui` — opens Playwright UI mode
- **CI runs this suite and it BLOCKS MERGE** (the `playwright` job in `.github/workflows/ci.yml`, sharded 3×, on every PR and every push to `main`/`release`). It collects the `e2e` tier that `config/feature_shapes.yml` demands of the `ui+db` and `onchain-vertical` shapes.
- **`@quarantine`**: the specs already rotted when the lane was switched on (2026-07-13), excluded in CI via `--grep-invert @quarantine`; CI runs the `executed` count from `config/e2e_lane.yml`. That hole is ratcheted by `test/lib/e2e_quarantine_ratchet_test.rb` — the count may fall, never rise. Repair lands cluster by cluster, so look the current ticket up on the board rather than trusting a slug pinned here: `/tasks/repair-quarantined-e2e-clusters` took the first three (2026-08-18), and this bullet cited `/tasks/repair-rotted-e2e-specs` as live long after that task was archived with all 18 specs still tagged — the trap catalogued in `docs/agents/agents/xan/sops/clean-up.md`. Never add a tag to green a PR; the ratchet goes red.
- **Config**: `playwright.config.js` — Chromium only, defaults to port 3000, accepts `E2E_PORT=<port>`, auto-starts test Rails server with local email capture enabled
- **Seed**: `e2e/seed.rb` — an admin user (`alex@test.com`) plus **22 models across ~20 tables**: agents, skills + assignments, tasks + task_events, activities, agent_activities, agent_actions, action_grades, pokemons, session_mascots, releases, gate_runs, coaches, teams, people, usages, error_logs. Idempotent via `delete_all`. **Eight of those tables have NO fixture** (`action_grades`, `agent_actions`, `agent_activities`, `gate_runs`, `pokemons`, `releases`, `session_mascots`, `task_events`) — do not trust this list to stay current, ask the code: `TestDatabasePurge.unfixtured_tables` names all 45 un-fixtured tables of the 73 in the schema. (The old entry here read "1 admin user, 2 agents, 2 skills, 3 tasks, 2 activities" — that undercount is precisely what let the pollution bug hide.)
- **Cleanup**: none needed — **the minitest database is hermetic by construction.** `test/test_helper.rb` runs `TestDatabasePurge.purge!` at load (and again in each parallel worker), truncating every application table before fixtures load, so rows any other process committed — the e2e seed, a stray `bin/rails runner`, a killed test — cannot reach a test. The old hand-reset ritual (`RAILS_ENV=test bin/rails db:test:purge db:test:prepare` after e2e work) is designed out; you no longer run it. The release gate (`bin/release.rb`) still performs a reset in its own gate workspace before running the whole Ruby suite — the SYSTEM tier too (`bin/rails db:test:prepare test test:system`), resolved from `ci.yml` — but the reset is no longer the thing that saves you. Since the hub's CI suite was **sharded** (2026-08-20) that resolution is no longer a verbatim copy of one CI step: CI runs the suite as a 4-way `bin/ci-shard` matrix plus a separate `system` job, and the gate runs the single command whose scope is their union. `bin/lib/ci_test_command.rb` states the argument and `test/lib/rails_lane_contract_test.rb` asserts the union really is the whole tree.
- **The purge FAILS CLOSED.** It empties every table, so it refuses to run unless it can *prove* the connection holds this app's test database: `RAILS_ENV` must be `test`, and the connected DB (read back from the live connection) must be the `database:` literal `config/database.yml` declares for `test` — or a legitimate derivative (`…-0` parallel clones, `…_<worktree>` isolated DBs, and the release gate/ship workspaces' `<app>_gate_test` / `<app>_ship_test`, which are admitted as an **exact** set derived from the base, never by a prefix rule that would also admit `…_development`). It raises `TestDatabasePurge::UnsafeDatabase` rather than truncate anything it cannot vouch for. Never rescue that error to "get the suite running": it means the suite was about to empty a database that is not the test database.
- **Helper**: `e2e/helpers.js` — `loginWithMagicLink(page, email)` requests a link, reads `/_studio/local_emails.json`, confirms, and consumes it.
- **Spec files**: the count lives in `config/e2e_lane.yml` (`total_specs`), not here — and for the file count ask the runner, `npx playwright test --list`, never the `--list` receipt commented above that key, which is prose no guard reads and is stale today — `smoke.spec.js` (page loads, passwordless auth, nav links, theme toggle) plus the board, task-card, timeline, agent-activity, heartbeat, deployments/live-update, mascot, pricing, release, and testing-gates suites.

## Test invocation gotchas

System Ruby 2.6 is on PATH by default on macOS and breaks `bundle exec`. If tests fail with `cannot load such file -- socket` or `Could not find 'bundler' (2.4.19)`, prepend the brew Ruby PATH:

```bash
PATH="/opt/homebrew/opt/ruby@3.3/bin:/opt/homebrew/lib/ruby/gems/3.3.0/bin:$PATH" bin/rails test
```

See `docs/agents/system/house-burn-down.md` gotchas 1 and 5 for context.
